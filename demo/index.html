02 — Streaming preview

The app runs on the host. The browser gets pixels.

QALA's delivery layer in miniature. A separate process plays the QALA host: it runs the app, draws each screen, burns in the session watermark and sends compressed frames. Your browser only shows frames and sends back clicks, and the gateway passes those clicks to the detector. Simulated here: a Web Worker stands in for the host. In production it is an Apache Guacamole session on our servers.

04 — Benchmark

Numbers computed here, not typed.

Every attacker profile runs 100 times through three defences: a plain rate-limit rule (more than 25 actions a minute), QALA v1 with calibrated weights, and QALA v2, which adds a logistic-regression model trained on 10,612 labelled session prefixes. v2 was trained on seed 4242 and checked on seed 9191, so seed 777 is held-out data. Rerun with a new seed and the numbers move a little. That's the point.

05 — Disclosure

What this is, and isn't.

The model

v1: a transparent weighted logistic classifier over seven named behavioural features (speed, timing regularity, coverage, forward sweep, pointer movement, backtracking, dwell) plus a honeypot rule, with every weight and contribution shown live. v2: averages v1 with a logistic-regression model trained on 10,612 labelled prefixes from 1,000 simulated sessions (seed 4242, class-balanced, L2). Its threshold was checked on validation seed 9191 and it is tested on held-out seed 777. The trained model leans on pointer movement, which real agents can fake, so pilot data comes next.

The data

Synthetic sessions plus your own, generated in your browser. Attacker profiles are statistical event generators. No external data, no network calls, and no personal data leaves the page.

The components

Vanilla JavaScript, Canvas and a Web Worker, no external libraries. The streaming preview uses a worker as the host and JPEG frames as the stream. In production the streaming layer is Apache Guacamole (Apache-2.0) and the detector runs server-side on the session event stream.

Production input

Only the event stream the streaming gateway already has: navigation and action events with timestamps, pointer-movement presence, and which screens were touched. No app instrumentation and no content capture.

Honest limits

A low-and-slow agent that paces itself and copies backtracking stays under the threshold most of the time. Mitigations on the roadmap: more honeypots and cross-session aggregation (one account slowly mapping an app over days). Filmed screens are deterred by the visible session ID, not prevented.
